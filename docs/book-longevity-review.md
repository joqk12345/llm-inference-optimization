# 十年可用性审稿与重构方案

> 目标不是预测 2036 年会流行什么，而是让读者在更换模型、硬件和推理引擎后，仍能用本书定位瓶颈、设计实验并做出取舍。

## 一、审稿结论

当前稿件已经有一条可读主线：动机与全景 → 基础 → KV/调度/量化/投机 → 生产 → 高级话题。主要问题不是缺少技术，而是**稳定知识与版本知识混在同一叙事层**：章节标题和正文频繁以 vLLM、GPU 型号、模型名称和年份组织内容；部分“趋势”段落实际上是尚未证实的产品判断；同一概念（KV、PagedAttention、continuous batching、PD 分离）在第 5、6、7、10、11 章多次出现；第 11 章同时承担 Agent、异构硬件、MoE、多模态、RL 和前沿新闻，边界最不稳定。

因此建议保留现有 11 章作为**迁移期兼容目录**，不立即大规模改名；在下一版逐步重排为“稳定内核 + 机制专题 + 生产闭环 + 可替换适配层”。这样旧链接不失效，同时把会过期的内容从主叙事中隔离出来。

### 十年后仍应成立的核心命题

1. 优化先从 SLO、质量、成本和负载开始，而不是从某个参数开始。
2. prefill 与 decode 的工作负载不同；端到端指标必须分解测量。
3. 状态（KV、混合注意力状态、前缀和会话上下文）是容量、调度和复用问题的共同核心。
4. 吞吐、延迟、质量、显存、通信和复杂度之间不存在免费午餐。
5. 任何优化都必须用固定负载、基线、质量门槛和回滚方案验证。
6. 生产推理是一个可观测、可扩缩、可降级、可持续运营的系统，而不只是一次模型调用。

### 应从主线降级的内容

- 特定年份的 GPU 产品线、价格、市场规模和“成为标配”的预测。
- 单一框架的内部类名、指标名、启动参数和默认值。
- 尚无可复核证据的倍率、成本下降比例和“Day 0”叙事。
- 把一个模型或论文当作未来方向的唯一代表。

## 二、推荐的目标架构

### Part I：问题定义与测量（稳定内核）

1. **推理系统优化的目标函数**：质量约束、SLO、吞吐、成本、能耗和复杂度；建立 workload card 与 baseline card。
2. **生成工作负载的机制**：token、prefill/decode、Attention、采样、延迟分解和 roofline 思维。
3. **硬件与运行时抽象**：计算、显存、带宽、通信、并行和 kernel；只讲能力维度，不按厂商目录写历史。
4. **基准、剖析与实验方法**：TTFT、ITL/TPOT、E2E、吞吐、P95/P99、显存、质量、错误率和成本的统一口径。

### Part II：状态与执行机制

5. **KV 与其他推理状态**：缓存生命周期、分页/块化、碎片、前缀复用、量化、offload，以及混合状态的统一抽象。
6. **批处理与调度**：static/dynamic/continuous batching、fairness、admission control、token budget、优先级和 backpressure。
7. **模型表示与数值精度**：FP/INT、weight-only、W8A8/W4A16、KV 量化、校准、质量评估和硬件 kernel 约束。
8. **减少串行步数与通信**：speculative decoding、并行解码、PD/EP 分离；以“何时有效、何时失败”组织，而非按项目罗列。

### Part III：系统设计与运营闭环

9. **单机到多机部署**：并行策略、网络、拓扑、故障域、模型制品和配置管理。
10. **SLO、容量与成本治理**：观测、压测、容量模型、弹性、限流、降级、灰度、回滚、ROI 和能源。
11. **复杂工作负载**：Agent 多轮上下文、MoE、多模态、rollout/RL；每个专题都使用同一诊断模板，不再作为“新闻汇编”。

### Part IV：适配层（独立更新）

- Runtime cards：vLLM、SGLang、TensorRT-LLM、llama.cpp 等。
- Hardware cards：GPU、CPU、NPU、TPU、边缘设备的能力矩阵。
- Model cards：Dense、MoE、GQA/MLA、混合注意力、多模态模型。
- Playbooks：安装、命令、Kubernetes YAML、版本兼容矩阵和故障排查。

适配层每个条目必须有“验证日期、适用版本/硬件、测试命令、已知限制、替代路径和归档日期”；它不是正文的理论依据。

## 四、每章统一模板

每章开头固定回答：**本章解决什么问题、假设读者已知什么、明确不讨论什么**。每个优化技术固定使用以下顺序：

1. 问题与适用负载（workload card）。
2. 不优化时的 baseline。
3. 机制解释（与框架无关的抽象）。
4. 可观测信号与诊断方法。
5. 实验设计和质量门槛。
6. 成本、复杂度、故障和回滚。
7. runtime/hardware/model 适配卡。
8. 小结、检查清单和下一章决策。

所有性能数字必须同时给出模型、输入/输出长度、并发、硬件、精度、runtime commit、warm-up、指标分位数和质量评测；缺一项就改写成定性结论或标为“示意”。

## 五、迁移顺序与验收标准

### 第一阶段：先消除误导（当前版）

- 在第 2、3、4、8、9、11 章的开头标注时效边界。
- 将“趋势/未来/标配/革命”等判断改成可证伪的条件句。
- 修复章节编号、内部链接、绝对本地路径和 `latest` 镜像示例。
- 统一指标词汇：TTFT、ITL/TPOT、E2E、goodput、P95/P99，并说明测量范围。

### 第二阶段：抽取稳定内核

- 把第 5 章压缩为机制导论，把 KV 细节集中到第 6 章、调度细节集中到第 7 章。
- 新增“实验与基线”章节（目标目录 Part I 第 4 章），让读者先学会证明优化有效。
- 把 runtime、hardware、model cards 从正文移到 `docs/cards/`，并给每张卡自动检查元数据和验证日期。

### 第三阶段：形成持续维护机制

- 每次版本更新只允许修改适配卡和案例数据，不随意改稳定章节的概念定义。
- 每个案例保留原始命令、环境 manifest、原始结果和失败结果；没有复现实验就不得写成结论。
- 每年做一次“时间胶囊审阅”：从正文删除已失效的默认值、产品比较和价格；保留机制、实验方法和历史背景。

验收以结构而非字数为准：核心章节中至少 80% 的小节不依赖具体框架/型号；所有数字都有实验上下文或证据等级；全仓库不存在本地绝对链接；新读者只读稳定内核也能完成一次 baseline→profile→优化→回归的闭环。

## 六、编辑决策

本书最值得长期保留的定位不是“某年某框架的参数大全”，而是**推理系统性能工程的诊断与决策教材**。因此本次重构采取“兼容迁移”而不是推倒重写：保留现有章节 URL，先把稳定原则前置、把重复内容归并、把易变内容卡片化，再用真实可复现实验逐步替换现有示例。这样读者在十年后即使面对不同的模型、芯片和 runtime，仍能沿用同一套问题分解和证据标准。
